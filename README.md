# explain

一个 Claude Code skill：**讲清一个东西，四块，60 行以内。**

核心判断很简单——

> 讲解失败的原因几乎不是"讲少了"，而是"一节接一节，每节都很长"。
> 所以限长比结构重要：宁可少讲一块，不许加长一块。

## 四块

| 块 | 在干什么 | 硬要求 |
|---|---|---|
| 1. 是什么 | 让人先知道"我在听什么" | 一句话，能拆成 2~3 个词 |
| 2. 人是怎么做的 | 用生活过程铺出结构，再逐句翻译 | 编号故事 1~7 + 一张翻译表 |
| 3. 为什么非得这样 | 把"设计"还原成"欠账" | 成本表 + 至少一个数字 |
| 4. 它什么时候骗你 | 交付边界，让人能自己判断错在哪 | 外推断点 + 一个动作 |

每块最多一个表或一个列表。四级标题都不许有。

## 两个示例（压缩版，只示形状）

**Robot navigation**

- 是什么：从我现在的位置，走到我要的位置。起点、终点、路——三样都知道就叫查地图，不叫导航。
- 人怎么做：你妈喊你找剪刀 → 想"一般在抽屉" → 边走边看 → 先翻书桌 → 没有 → 改判断 → 三处都没有 → 别猜了，全屋翻 → 看到就停。翻译表右列是"确定了什么 / 没确定什么"。
- 为什么非得这样：人免费拿四样（位置感、常识、东西还在原地、敢放弃），机器人得一样样用算法补回来——导航的架构不是设计出来的，是这四笔账逼出来的。错误先验把 41.7% 打到 30.5%。
- 什么时候骗你：这比喻只管到"东西还在老地方"为止。再往下推出"找得慢是因为走得慢"就错了——人找东西慢都是猜错地方。

**Diffusion**

- 是什么：把一个东西一步步弄乱，再学着自己一步步收拾回来。
- 人怎么做：一张干净画 → 撒一层沙 → 再撒 → 50 层后成了灰纸 → 但你记下了每层撒的是什么 → 生成时拿新灰纸，一层层扫回来。
- 为什么非得这样：直接输出一条轨迹只能得到所有路线的平均值；想算最优要 TSP，48.3 秒一次。50 步小修正 = 0.996 秒，SR 只掉 3 个点。
- 什么时候骗你：只管到"沙是均匀撒的"为止。再推出"多步一定更好"就错了——步数收益会饱和，所以才有蒸馏。

## 安装

```bash
git clone https://github.com/Hiaa1/explain.git ~/.claude/skills/explain
```

放进 `~/.claude/skills/` 对所有项目生效；放进项目里的 `.claude/skills/` 只对该项目生效。

## 适用边界

买的是**可复述、可判断**，卖的是**覆盖面**。做讲解、写笔记、给论文方法做定位划算；赶时间要一个清单答案时不划算。
